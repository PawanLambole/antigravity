# Project Information & Architecture Analysis

Your task is to completely analyze and understand the project.

Do not modify, create, delete, or refactor any files. This workflow is only for analyzing and documenting the project.

## 1. Project Overview

Identify and explain:

- Project purpose
- Main functionality
- Type of application
- Major features
- Platforms included in the project

## 2. Technology Stack

Identify all major technologies used, including:

- Programming languages
- Frontend frameworks
- Backend frameworks
- Mobile technologies
- Database
- Authentication
- APIs
- State management
- UI and styling libraries
- Build tools
- Package manager
- Cloud services
- Third-party integrations

Include important versions where available.

## 3. Project Architecture

Analyze and explain the complete architecture of the project.

Identify:

- Frontend architecture
- Backend architecture
- Database architecture
- API architecture
- Authentication flow
- Authorization and user roles
- Data flow
- Communication between different modules
- Communication between different platforms

Explain how all major parts of the project work together.

## 4. Directory Structure

Generate a clean and readable directory structure.

Include:

- Important folders
- Important files
- Main modules

For each important folder and file, explain its purpose.

Ignore unnecessary generated folders and files such as dependency folders, build output, caches, and other irrelevant system files unless they are important to the project.

## 5. Important Files and Modules

Identify the important files and explain:

- Their purpose
- Their responsibility
- Which modules depend on them
- How they connect with other parts of the project

Focus on important files rather than explaining every generated or dependency file individually.

## 6. Application Modules

Identify the major modules and explain:

- Purpose of each module
- Main functionality
- Important components
- Services used
- Dependencies between modules

## 7. User Roles and Access

Identify all user roles in the project.

For each role, explain:

- Purpose
- Available functionality
- Permissions
- Main workflow

## 8. Database Structure

If the project uses a database, analyze:

- Database provider
- Important tables or collections
- Relationships
- Main data flow
- Authentication-related data
- Storage if applicable

## 9. API and Integration Structure

Identify:

- APIs
- Backend services
- External integrations
- Third-party services

Explain how the application communicates with them.

## 10. Application Flow

Explain the overall application flow from start to finish.

Include:

- Application startup
- Authentication flow
- Navigation flow
- User actions
- API communication
- Database interactions

## Final Report

Provide the final project information in this format:

1. Project Overview
2. Technology Stack
3. Complete Architecture
4. Directory Structure
5. Important Files and Their Purpose
6. Major Modules
7. User Roles
8. Database Structure
9. API and Integrations
10. Application Flow
11. How All Parts Work Together

Use clear and simple explanations.

Do not modify any code or files.

Your only objective is to provide a complete understanding of the existing project, its architecture, structure, and implementation.
